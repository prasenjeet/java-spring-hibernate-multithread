10 threads race to decrement the same product's stock. Hibernate's @Version field catches conflicts; an exponential-backoff retry loop guarantees zero lost updates.

Pessimistic Locking

20 bidirectional bank transfers run simultaneously. Canonical ascending-ID lock ordering prevents deadlocks; money is perfectly conserved across all transfers.

Pattern 4
REQUIRES_NEW Batch

Parallel Batch Processing

20 orders are split into 4 batches of 5 and processed in parallel. Each batch runs in its own REQUIRES_NEW transaction — one failure per batch is isolated and won't roll back the others.

Pattern 5
EntityManager flush/clear Bulk Insert

Session-per-Thread (Bulk Insert)

200 products are inserted across 4 threads. Each thread manually opens its own EntityManager, writes 50 rows, calls flush()/clear() to prevent memory bloat, then commits and closes its session — without any Spring @Transactional proxy.
